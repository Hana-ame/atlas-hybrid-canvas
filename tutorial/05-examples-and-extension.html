05 · 画布内置示例拆解与二次开发实战

这一章把画布首屏能直接点、直接拖的 4 组示例（eg）逐个扒开讲透实现原理，再给出 4 套可直接照抄的二次开发套路：加新模板、加新 UI 块、加新脚本 API 与加自动化测试。

一、屏幕上 4 组内置示例的实现原理

示例 1：核心架构枢纽（node-world-hub）——经典按钮 + 改背景 + 代理请求

这张卡位于左上角 ZONE A，演示的是不写整套流式 UI 时最轻量的交互方式：通过 buttons 数组挂载 3 个动作按钮：

  • 本地计数 +1：调用 lib.inc('visits', 1)，结果仅写入当前浏览器 IndexedDB 的 overlay.runtimeVars，不污染后端底座。
  • 切换 ZONE A 背景色：调用 canvas.setAnnotationBg('ann-zone-0', color, 0.9)，Worker 返回 annotationOps，主线程写入 overlay.annotationOverrides 并触发底层 ChunkUnderlayCanvas 重绘。
  • 经服务端代理测试 GET：按钮 actionType: 'proxy_http'，点击后主线程 POST 到 /api/proxy，由服务端完成白名单/DNS 校验后再代发外网请求。

示例 2：一键创建并联动控件（example-spawner）——动态生成子卡与双向通信

位于 ZONE B 下方，完整展示了「代码生成界面 + 脚本动态造节点 + 跨控件消息」三件套：

  1. 首次自动渲染：等 overlayHydrated 就绪后，App.tsx 自动给它发一次 { kind: 'render' }，脚本产出的 vars.contents 立刻渲染出按钮行与输入框。
  2. 动态创建子控件并连线：点「+ 创建子控件」触发 on('spawn')，调用 widgets.create({ dx: 470, dy, connect: '联动 #n', script: childScript })。Worker 把创建指令放进 widgetOps，主线程同步写进 base.nodes 与 base.edges，并立刻帮新子卡跑一次 render。
  3. 回车发送与双向回信：输入框绑定 bind: 'draft' 与 onSubmit('msgInput')，内部用 emitDownstream('ping', { text }) 并发扇出投递给所有已连线的下游子卡；子卡收到 on('ping') 后更新 vars.inbox，点子卡按钮又能反向 emit(vars.parentId, 'childReply', ...) 回传主卡。

示例 3：ZONE D 三节点连线数据通路（demo-flow-*）——端口驱动、零硬编码 ID

这组示例由「① 任务清单」→「② 数值发生器」→「③ 连线数据汇总」组成，展示了连线作为真实数据管道的底层原理： 

// ③ 下游消费者：不写死任何上游 ID，直接按入口端口读取连入的节点
const checklistIn = widgets.inputs('in-1'); // 读取连入 in-1 的上游（含 body 正文）
const numIn = widgets.inputs('in-2');       // 读取连入 in-2 的上游（含 vars 变量）

// 统计上游清单正文里的 - [] / - [ ] / - [x]
for (const src of checklistIn) {
  for (const line of String(src.body || '').split('\n')) {
    const m = /^\s*[-*+]\s*\[([ xX]?)\]/.exec(line);
    if (m) { total++; if (m[1].toLowerCase() === 'x') done++; }
  }
}

// 接收上游通过 emitDownstream('boost', payload) 沿线推送的事件
on('boost', (payload, meta) => {
  vars.bonus = (Number(vars.bonus) || 0) + (Number(payload?.delta) || 1);
});
  • 为什么勾选上游复选框右侧会瞬间更新？ handleEditBody 在更新上游 body 的同时，会扫描 edgesRef.current 找出所有连在下游的脚本控件，带上 peerOverrides: { [nodeId]: { body: nextBody } } 立刻触发一次 render，无须等待 React 下一轮渲染。
  • 为什么删线或重连也会实时更新？ onConnect（先过 validateDagConnection 防成环）与 onEdgesChange 都会用最新的 edgesOverride 立刻重跑下游脚本。

示例 4：vars 驱动形态演示（demo-var-morph & 左侧 tpl-var-morph）

这张卡展示了 React Flow 节点如何被脚本变量直接变形、变色和移动，且不与手动拖拽冲突： 

on('cycleMode', () => {
  vars.type = 'ALERT';          // 改左上角徽标
  vars.title = '告警模式';        // 改卡片标题
  vars.color = '#DC2626';       // 改顶边与徽标配色
});
on('toggleSize', () => {
  vars.width = 480;             // 自动钳位 180–1400
  vars.height = 270;            // 自动钳位 100–1200
});
on('nudgeRight', () => {
  vars.pos = { x: ctx.entity.x + 80, y: ctx.entity.y }; // 移动坐标并刷新 Chunk 索引
});
不弹回原理：resolveEffectiveNodes() 把 vars 投影到节点属性；一旦用户随后手动拖动、拉边缩放或双击改标题，clearConflictingRuntimeVars() 会自动删除 runtimeVars 里冲突的布局键（保留 modeIdx / expanded 等业务变量），确保手动操作始终接管。

二、二次开发实战指南（4 个高频场景）

场景 1：给左侧模板抽屉加一个新预设控件

打开 src/core/widgetTemplates.ts，在 BUILTIN_TEMPLATES 数组里追加一项即可自动出现在左侧可拖放面板中。关键细节：多行脚本一律使用 String.raw`...`，防止 JS 模板字符串吞掉 \n 与正则 \s 转义： 

{
  id: 'tpl-my-timer',
  name: '倒计时小组件',
  description: '记录目标分钟数并向连线右侧下游推送完成事件',
  group: '知识地图', // 须匹配 TemplateGroup 联合类型
  kind: 'node',
  color: '#7C3AED',
  nodePreset: {
    width: 320,
    height: 185,
    title: '番茄钟',
    body: '',
    category: '计时',
    color: '#7C3AED',
    defaultVars: { mins: 25 },
    script: String.raw`vars.contents = [
      { type: 'text', text: '专注时长：' + vars.mins + ' 分钟', align: 'center', bold: true },
      [
        { type: 'button', id: 'm5', label: '+5 分钟', variant: 'primary' },
        { type: 'button', id: 'done', label: '完成并推送下游', variant: 'success' }
      ]
    ];
    on('m5', () => { vars.mins = (Number(vars.mins) || 25) + 5; });
    on('done', async () => { await emitDownstream('pomodoroDone', { mins: vars.mins }); });`,
  },
}

保存后直接跑 npm test，tests/scriptSandbox.test.ts 会自动扫描并编译校验你的新模板脚本是否触发黑名单或语法错误。

场景 2：在 vars.contents 中扩展一种新的声明式 UI 块（如进度条）

  1. 声明类型：在 src/core/types.ts 的 ContentLeafBlock 联合类型中新增 | { type: 'progress'; value: number; max?: number; color?: string }。
  2. 渲染组件：在 src/canvas/WidgetNode.tsx 的 renderLeafBlock() 中新增 if (block.type === 'progress') { ... } 分支（记得可交互子元素加 nodrag nopan 并拦截 onMouseDown / onPointerDown）。
  3. 直接生效：Worker 沙箱只透传纯 JSON 的 vars.contents，不需要改沙箱代码就能在所有控件脚本里使用新 UI 块。

场景 3：向脚本沙箱注入一个新的能力（如 lib.uuid() 或新指令）

  • 纯计算工具（如 lib.uuid / lib.formatDate）：直接在 src/core/scriptSandbox.ts 的 workerBootstrap 字符串里的 const lib = { ... } 添加即可，零主线程通信开销。
  • 需要修改画布/外部状态的副作用指令：遵循「Worker 收集操作数组 → postMessage 回传 → 主线程 App.tsx 统一落地」的单向指令模式（参考 annotationOps、widgetOps、emitOps），切勿向 Worker 暴露 DOM 或直接网络权限。

场景 4：接通自托管后端、配置密钥与写回归测试

二开需求 修改位置与验证命令
接入真实外部 API（带密钥） 在 .env 配置 PROXY_UPSTREAM_BASE_URL、PROXY_API_KEY、PROXY_ALLOWED_HOSTS、PROXY_CLIENT_TOKEN，运行 npm run dev 即可通过 /api/proxy 安全转发。
开启管理员发布鉴权 服务端配置 BLUEPRINT_SAVE_KEY；静态 Pages 模式可在构建环境变量配置 VITE_MOCK_SAVE_KEY。
替换内存蓝图存储为数据库 将 server/server.ts 中 serverBaseBlueprint 替换为 SQLite / PostgreSQL 读写，接口契约（GET /api/blueprint、POST /api/blueprint/publish）保持不变。
新增业务逻辑单测 在 tests/ 新增 *.test.ts（基于 Node 原生 node:test + node:assert/strict），执行 npm test && npm run typecheck 即可完成回归。
