04 · 双层存储、多人协同与后端安全

为了让同一张画布既能公开给访客自由交互体验，又能安全地由管理员发布权威版本、支持多人实时协同与安全调用外部 API，系统在存储、同步与后端代理上做了严格的边界隔离。

双层状态模型：为什么访客怎么玩都不会污染后端？

  • 权威底座（BaseBlueprint）：由管理员持有密钥（X-Blueprint-Save-Key）发布到后端，包含所有节点/注释/连线的默认结构与 defaultVars。
  • 个人叠加层（LocalOverlayState）：普通用户在浏览器里拖拽位置、勾选复选框、运行脚本产生的 runtimeVars 与背景变色，全部异步写入本地 IndexedDB（数据库 atlas-hybrid-canvas-db）。点击顶栏「重置本地状态」即可一键恢复权威默认。

防抖写盘、多标签页同步与 50 步撤销栈

  • 300ms 防抖 + 兜底刷盘（useOverlaySync.ts）：高频输入与勾选自动合并为 300ms 一次写盘，并在 beforeunload / pagehide 时立即刷盘防丢失。
  • BroadcastChannel 单指纹跨页签同步：同一浏览器开两个页签时，通过 lastSyncedFingerprintRef 去重同步本地叠加层——既避免多条消息合批引发 A→B→A 回环，也不会在 S2 → S3 → S2 回退时误跳过写盘。
  • 50 步安全撤销栈（useBlueprintHistory.ts）：使用 safeClone()（原生 structuredClone + JSON 降级兜底），彻底杜绝浅拷贝污染历史快照。

Go 多人协同房间与确定性 CRDT

room-go/ 目录内置了独立的 Go WebSocket 房间服务（含 room_test.go 与 store_test.go），前端通过 src/core/roomClient.ts 接入。多端并发编辑同一实体时，两端执行完全一致的确定性 LWW 裁决函数 beats(incoming, current)： 

// 先比版本号 rev，较大者胜出；rev 相等时按客户端 ID (cid) 字典序确定性裁决
if (incoming.rev !== current.rev) return incoming.rev > current.rev;
return incoming.cid > current.cid;

后端鉴权与防 SSRF 密钥代理（server/）

接口 / 配置 安全机制说明
POST /api/blueprint/publish 校验 X-Blueprint-Save-Key 与环境变量 BLUEPRINT_SAVE_KEY，先比字节长度再用 crypto.timingSafeEqual 常量时间比较，防时序攻击；请求体上限 10mb。
POST /api/proxy ① 目标域名必须命中 PROXY_ALLOWED_HOSTS 白名单；② 经 DNS 解析拦截 127.0.0.1、RFC1918 内网、169.254.169.254 云元数据与 IPv6 ULA；③ 剥离 Host / Cookie 等危险请求头；④ 仅在服务端注入 PROXY_API_KEY，前端永不接触密钥。
限流与调用方令牌 按客户端 IP 执行滑动窗口限流（PROXY_RATE_LIMIT_PER_MIN，默认 30 次/分钟，超限返回 429 + Retry-After，且每 5 分钟 / 超 200 条目自动回收过期桶）；支持可选 PROXY_CLIENT_TOKEN（X-Proxy-Token）。
静态部署 Mock 模式 构建部署到 GitHub Pages 时，src/core/mockApi.ts 自动在浏览器端拦截上述契约并用 IndexedDB 模拟（默认演示密钥 atlas-demo-key，可通过 VITE_MOCK_SAVE_KEY 覆盖）。
