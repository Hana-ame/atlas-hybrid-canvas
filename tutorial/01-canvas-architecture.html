01 · 混合无限画布与渲染原理

纯 DOM 白板在几百个节点下缩放会掉帧，纯 Canvas 自绘输入框又会在中文 IME、缩放定位和无障碍上踩坑。Atlas Hybrid Canvas 把两者按缩放层级（LOD）切开：近景用 React Flow DOM，远景无缝交棒给 512×512 离屏瓦片 Canvas。

迟滞 LOD（Hysteresis LOD）：为什么阈值是 32% 和 38%？

如果只设一个单一阈值（比如 35%），用户在 35% 附近轻轻滚动滚轮，DOM 节点会反复挂载和卸载导致剧烈闪烁。系统在 App.tsx 中采用了带迟滞带的双阈值状态机：

  • 进入宏观（Macro）：仅当缩放比 zoom < 0.32 时，卸载全部上层 React Flow DOM 节点，底层 ChunkUnderlayCanvas 接管绘制全部简化色块与贝塞尔连线箭头。
  • 回到近景（Meso / Micro）：必须把滚轮放大到 zoom > 0.38 才会重新挂载当前可见区块的 DOM 节点；介于 32%–38% 之间保持当前模式不变。

如何根治 React Flow v12 拖拽频闪？

React Flow v12 内部依赖每个节点的 measured（真实宽高）与 dragging 标记。如果每次状态更新都从零重新 map 出新数组覆盖 nodes，节点会在测量完成前短暂变为 visibility: hidden，表现为拖拽或平移时的剧烈闪烁。项目通过三道防线彻底消除：

  1. 受控增量合并：在 App.tsx 中维护 rfNodes 状态，拖动过程中严格通过 applyNodeChanges(changes, prev) 原地更新，保留 measured / dragging / selected。
  2. 粗粒度视口桶（viewportBucketKey）：仅当视口跨越半个 Chunk 边界时才重新计算可见节点集合，平移每像素绝不触发 React 重渲染。
  3. 底层 Canvas 零重渲染跟随：ChunkUnderlayCanvas.tsx 直接通过 useStoreApi().subscribe() 订阅 React Flow 内部的 transform 矩阵，在 requestAnimationFrame 中直接重绘底层画布。

512×512 空间分块、LRU 瓦片与显存回收

ChunkManager 把无限二维世界划分为 512×512 像素的区块，任意跨区块的大卡片会同时登记到它覆盖的所有 Chunk 中。ChunkTileCache（默认上限 160 张离屏瓦片）负责缓存静态瓦片：

  • HiDPI 清晰文字：在近景（meso/micro）下，背景文字注释直接按 devicePixelRatio 实时绘制在主 Canvas 上，杜绝二次缩放发糊；背景插图采用 contain 严格等比缩放，绝不拉伸变形。
  • 主动释放 GPU 显存：当 LRU 淘汰旧瓦片或调用 clear() 时，显式执行 tile.canvas.width = 0; tile.canvas.height = 0;，促使浏览器立即释放离屏图形缓冲区。
  • 大图等比自动压缩：在 AnnotationNode.tsx 上传超过 180 KB 的本地图片时，自动在浏览器端等比缩放到长边 ≤ 1280px（WebP/PNG，0.82 质量），避免几 MB 原图撑爆 JSON 导出与保存。
实用技巧：点顶栏「压测大地图」可一键在 4×4 个区块铺入近 400 个节点；先在近景拖动感受流畅度，再把滚轮缩到 25% 观察宏观瓦片与贝塞尔箭头无缝接管。
