双层状态驱动混合渲染，统一 mockApi 收口全部接口流量

系统由四条解耦良好的主干组成：前端以 BaseBlueprint（权威蓝图）加 LocalOverlayState（个人叠加层）维持渲染与交互；所有控件脚本在一次性 Web Worker 中运行并受信任弹窗门禁约束；v61 起 src/main.tsx 无条件挂载 mockApi，使开发态与生产态完全共享同一套 VITE_BACKEND_WS_URL 双模路由规则；后端以单进程 Express 加 WebSocket 承载蓝图、多 DPI PDF 解包、固定 IP 防重绑定代理和多人房间。

App.tsx 独占 21% 前端代码，已成为首要维护瓶颈

按源码行数统计，核心算法模块（chunkManager、viewportCulling、crdt、mediaHelper）均保持在 46–197 行的健康体量，内聚度极高。

失衡点集中在最上层的编排组件：App.tsx 达到 2,954 行，同时承担蓝图状态、撤销栈、协同房间同步、Worker 调度、控件回调与快捷键；WidgetNode.tsx 随新控件增加也涨至 880 行。

星型 WebSocket Hub 严格隔离多人底座与个人叠加层

多人协同不走 P2P，而是通过 server/roomServer.ts 构成星型中心转发。服务端与前端运行逐行等价的 (rev, cid) LWW 裁决函数，新成员入房拉取全量 state 快照，远端推送的脚本变更必须经过 ScriptTrustModal 审核。同一用户的本机多页签则通过 BroadcastChannel 仅同步 LocalOverlayState，不上行到房间，从而彻底避免多用户互相覆盖个人临时变量。

P0 · 拆解 App.tsx 与控件注册表

  • 将 App.tsx 拆为 useRoomSync、useScriptRuntime、useCanvasMutations 三个独立 Hook，把顶层容器压回 800 行以内。
  • 将 WidgetNode.tsx 改为声明式 Block 注册表，后续新增控件只需注册组件，不再修改主渲染树。

P1 · 服务端持久化与字段级合并

  • 将 sharedStore 与房间快照落盘到 SQLite（单机零运维）或 PostgreSQL / Redis，消除进程重启丢数据风险。
  • 将节点属性 LWW 从整卡粒度细化为字段级 fieldRev，消除同卡并发编辑互相覆盖。

P2 · 大文件传输与首屏分包

  • PdfViewerBlock、VideoNodeBlock 与 NodeInspectorPanel 改用 React.lazy 分包，将首屏主包压至 350 kB 以下。
  • WS RPC 遇到二进制体改走二进制 WebSocket 帧（ArrayBuffer header + body），去掉 33% base64 膨胀。
总体结论：Atlas Hybrid Canvas v65 的底座设计扎实、安全防线完整，适合直接作为原型或中小团队工具投入使用；真正决定它能否走向生产级多人产品的，只剩三件事——拆小 App.tsx、把内存存储换成真实数据库、以及给大文件上传去掉 base64 包装。
