双层状态叠加与双模式同构是整个系统的骨架

Atlas Hybrid Canvas 将画布状态拆分为共享蓝图底座（base）与本地叠加层（overlay）两层。共享蓝图通过字段级 LWW-CRDT（src/core/crdt.ts）在多端实时收敛，而用户的未发布草稿、脚本临时变量（runtimeVars）和标注微调先落在浏览器 IndexedDB 中（src/core/layeredStore.ts），渲染时由 resolveEffectiveNodes() 实时合成为最终视图，既保证协同不互相覆盖未提交编辑，又支持管理员一键发布回写底座。

在运行模式上，项目通过 src/core/apiCore.ts 实现前后端同构路由：未配置 VITE_BACKEND_WS_URL 时进入纯静态演示模式，src/core/mockApi.ts 拦截 /api/* 并在浏览器内按房间路径隔离写入 IndexedDB；配置后端或同源托管时，请求经 Express HTTP 或二进制 WebSocket RPC（/ws）直达 Node 后端，落盘到 <dataDir>/rooms/<key>.json 及其修改日志 .history.json。

全仓 57 个源码模块的职责分层与依赖链接

仓库采用单向依赖分层：src/canvas/* 与 src/components/* 只做受控渲染并向上回抛回调；src/hooks/* 编排副作用、快捷键、撤销栈与协同会话；src/core/* 承载全部与 React 解耦的纯逻辑（可直接在 Node 与浏览器两端复用）；server/* 则直接导入 src/core/apiCore.ts、crdt.ts 与 roomPath.ts，确保前后端算法 100% 同源。

HTTP REST、WebSocket 与 WebRTC 完整接口清单

服务端采用统一路由面：REST 既服务于首屏水合、管理员发布、版本历史回档与出站代理，也作为 WebSocket 不可用时的降级通道；WebSocket 承担实时协同状态同步、WebRTC 信令中继与跨站二进制 RPC 转发。

WS 协同帧协议

客户端发 upsert（携带 rev、cid 与逐字段 fieldRevs）或 delete；服务端以同源 mergeRecordFieldsLWW 裁决后广播给同房其他成员，防抖 1.5s 写入统一存储并记录去重后的 collab 历史。

WebRTC P2P 信令协议

入房后服务端推送 peers 列表，两端按 shouldInitiateRtcOffer(selfCid, peerCid) 确定性选主发起 rtc_offer，经 WS 中继交换 rtc_answer 与 rtc_ice，建链后在 DataChannel 上广播协同帧加速同步。

二进制 RPC 转发协议

跨站纯静态前端通过 rpcBinaryFrame.ts 封装 4 字节大端 JSON 头长度 + UTF-8 JSON 头 + 原始二进制载荷，经 /ws 零 base64 膨胀直传 PDF 等大文件给后端本地回环端口。

五道核心安全边界与 v85 整修后的防线

系统的安全模型严格区分「匿名协同层」与「高权限管理/代理层」：前端构建产物中永不嵌入静态密钥，所有高危能力均在 Node 服务端做强制校验。

1. 会话签发与管理密钥解耦

POST /api/auth/session 拒绝空 Origin 与非白名单来源（403），仅作为防自动化会话层；发布（publish）、回档（rollback）和挂载上游 PROXY_API_KEY 的 /api/proxy 均强制校验独立管理密钥（timingSafeEqual）。

2. 真实 IP 限流与 SSRF 钉死

默认忽略客户端自填的 X-Forwarded-For，以 req.socket.remoteAddress 计数限流（仅显式 TRUST_PROXY=true 才信任代理头）。出站代理在 DNS 解析后拒绝全部私网/回环/元数据 IP，并将 IP 钉死到 Socket 连接。

3. Web Worker 一次性脚本沙箱

每次控件脚本执行都启动独立 Worker 并在结束后立即 terminate()，超时 5 秒强制终止；运行时不可逆置空 17 个高危全局 API（含 Worker、SharedWorker、Blob、URL、WebTransport、WebAssembly 与全部网络接口），阻断嵌套 Worker 逃逸。

用法一：构建并启动生产级多房间服务

服务端入口由 esbuild 打包为单文件 dist-server/server.mjs，配合 dist/ 前端产物即可直接运行：

npm ci
npm run build
npm run build:server

AUTH_SESSION_SECRET="replace-with-32byte-random" \
BLUEPRINT_SAVE_KEY="admin-publish-secret" \
PROXY_ACCESS_KEY="proxy-admin-secret" \
TRUST_PROXY="true" \
ATLAS_DATA_DIR="/var/lib/atlas-data" \
PORT=8787 \
node dist-server/server.mjs

访问 https://your-host/team/design 自动进入 team/design 房间；同一路径的成员共享实时画布、WebRTC 直连加速与独立版本历史。

用法二：通过 API 执行版本发布、查询与回档

前端在同源加载时自动通过 POST /api/auth/session 获取 HttpOnly 会话 Cookie；管理员脚本或运维工具可按房间路径查询历史并回档：

# 1. 同源签发会话 Cookie
curl -c cookies.txt -X POST http://127.0.0.1:8787/api/auth/session \
  -H 'Origin: http://127.0.0.1:8787' \
  -H 'Content-Type: application/json' -d '{"cid":"ops-cli"}'

# 2. 查看 team/design 房间版本历史
curl -b cookies.txt http://127.0.0.1:8787/api/rooms/team/design/history

# 3. 回档至指定版本 v1（同步推送 replace:true 给全部在线成员）
curl -b cookies.txt -X POST http://127.0.0.1:8787/api/rooms/team/design/rollback \
  -H 'Content-Type: application/json' \
  -H 'X-Blueprint-Save-Key: admin-publish-secret' \
  -d '{"version":1}'

用法三：编写带响应式联动与拓扑校验的控件脚本

每个 Widget 节点均可挂载受沙箱隔离的统一脚本，通过 vars 读写状态、onChange 响应变量变化、onValidateConnect 声明连线规则：

// 当滑块或上游修改 temperature 时自动推导状态并通知下游
onChange('temperature', ({ next }) => {
  vars.alert = Number(next) > 80 ? '过热告警' : '正常';
  widgets.emitDownstream({ temp: next, alert: vars.alert });
});

// 控件自主声明禁止形成环路（可选，默认允许自由环路）
onValidateConnect(({ sourceId, targetId }) => {
  const dag = widgets.checkDag(sourceId, targetId);
  if (!dag.ok) return { allow: false, reason: '禁止闭环连接' };
  return { allow: true };
});
