## 本版背景
基于 v58 对整个仓库（`src/` 与 `server/` 共 42 个源码文件）执行全量静态代码审查，并配合真实无头 Chromium 全局端到端测试（桌面端 1440×900 全功能域 A–J + 移动端 390×844 M1–M3），修复了 5 处跨模块隐藏缺陷，直至连续 3 轮全局审查与全局浏览器 E2E 测试均保持 0 新 Bug、0 控制台报错与 0 未捕获异常。

## 修复内容

### 1. 协同房间 WebSocket 增量 CRDT 消息静默丢弃（`src/App.tsx`）
- **根因**：`handleConnectRoom` 仅处理了全量同步帧 `msg.t === 'state'`，对房间服务端广播的 6 类增量消息（`upsert_node`、`delete_node`、`upsert_ann`、`delete_ann`、`upsert_edge`、`delete_edge`）未作任何处理，导致多人协同时远端增量编辑无法实时反映到画布。
- **修复**：引入 `beats` 确定性 CRDT 比较，完整接入 6 类增量消息处理；远端 `upsert_node` 若携带脚本或 `proxy_http` 按钮且内容变更，自动触发 `ScriptTrustModal` 审阅门禁，防止协同脚本注入。

### 2. 删除连线未记录撤销历史（`src/App.tsx`）
- **根因**：`onEdgesChange` 中处理 `remove` 变更时直接删除了 `base.edges` 中的条目但未调用 `pushHistory()`，导致删除连线无法通过 Undo 恢复。
- **修复**：在批量删除连线前调用 `pushHistory()`，确保删线操作与节点增删改一致纳入撤销/重做栈。

### 3. 删除节点回调闭包过期与残留状态未清理（`src/App.tsx`）
- **根因**：`handleDeleteNode` 的 `useCallback` 依赖数组为空 `[]`（存在过期闭包风险），且删除节点时未清理 `renderedScriptsRef` 与 `scriptLogsByNode` 中的该节点缓存，长期增删节点会残留脚本日志条目。
- **修复**：补全依赖 `[pushHistory, executeUnifiedWidgetScript]`，并在删除节点时同步清理 `renderedScriptsRef` 与 `scriptLogsByNode`。

### 4. 导入外部 JSON 蓝图缺少数组与非有限数值校验（`src/App.tsx`）
- **根因**：`handleImportJSONFile` 仅检查 `typeof parsed.nodes === 'object'`，未排除 `Array.isArray(parsed.nodes)`，且未清洗节点坐标/宽高中的 `NaN`/`Infinity`，也未清空旧画布的 `scriptLogsByNode`。
- **修复**：增加严格对象结构校验与有限数值兜底清洗，导入成功时清空旧脚本日志缓存。

### 5. `/api/proxy` 服务端出站拉取补齐流式体积上限（`server/server.ts`）
- **根因**：`/api/proxy/binary` 与 `/api/pdf/unpack` 均已使用 `readResponseBufferWithLimit` 防止上游超大响应引发 OOM，但 `/api/proxy` 所用的 `serverFetcher.fetch()` 仍直接调用 `await res.arrayBuffer()` 无流式截断上限。
- **修复**：改为调用 `readResponseBufferWithLimit(res, 2 * 1024 * 1024)`（2MB 上限），超限时立即中止流式读取并返回明确错误，与二进制代理安全防线对齐。
