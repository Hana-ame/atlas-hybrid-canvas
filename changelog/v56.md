# v56 — 修复 4 处真实 Bug（左上拉伸弹回原位 / PDF 锁定后 ResizeObserver 失联 / apiCore 10s 定时器泄漏 / 复制节点丢自定义端口）

> 发布日期：2026-11-23

## 修复（Fixed）

1. **拖左边/上边/左上角拉伸控件或注释框后，松手坐标弹回原位（且无法 Ctrl+Z 撤销）**（`src/canvas/WidgetNode.tsx`、`src/canvas/AnnotationNode.tsx`、`src/App.tsx`）：
   - 原 `onResizeEnd` 只保存 `width` / `height`，丢弃了 React Flow 传入的 `params.x` / `params.y`；且 `handlePatchNode` 未将 `patch.x` / `patch.y` 写入 `nodePatches`，`handleResizeNode` 未调用 `pushHistory()`。
   - 现已将 `x / y / width / height` 完整落盘并接入 `pushHistory()`，四边四角任意方向拉伸松手均精准停留且可一键撤销。
2. **`PdfViewerBlock` 一次性加载完成后，拉伸控件不会自动升级 DPI**（`src/canvas/PdfViewerBlock.tsx`）：
   - 原 `ResizeObserver` 的 `useEffect` 依赖为空数组 `[]`，在从未锁定输入态（`!isLocked`）切换至已锁定查看态（`isLocked === true`）挂载新 `stageRef` DOM 后，旧 observer 仍绑在已卸载的 DOM 上，导致 `stageWidth` 永远卡在初始 440px。
   - 现将依赖改为 `[isLocked]`，切换后立即读取新容器宽度并重新 `observe`。
3. **`apiCore.ts` 代理请求的 10 秒超时定时器泄漏**（`src/core/apiCore.ts`）：
   - `handleProxy` 中 `setTimeout(..., PROXY_TIMEOUT_MS)` 在请求提前成功后从未 `clearTimeout`，高并发下持续堆积未回收定时器，也让 Node 进程/测试套件每次白等 10 秒退出。
   - 现于 `finally` 中立即 `clearTimeout(timeoutId)`，实测测试套件总耗时从 `14.3s` 降至 `4.4s`。
4. **复制控件丢失用户自定义的入/出端口**（`src/App.tsx`）：
   - `handleDuplicateNode` 原未复制 `inputPorts` / `outputPorts`，导致复制带自定义端口的节点后端口全部退回默认值；现已深拷贝保留。

- `npm run build`：`vite build` 通过（0 错误）
