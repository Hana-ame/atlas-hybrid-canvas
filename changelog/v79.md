# Atlas Hybrid Canvas v79 — Beta 架构极简收敛（三通道统一 + 零前端密钥 + 单一房间源）

## 架构收敛（不再背负老数据兼容包袱）
1. **彻底清除前端静态密钥（回归清晰的 2 层安全边界）**
   - 移除 `VITE_PROXY_CLIENT_TOKEN` 与 `PROXY_CLIENT_TOKEN` 静态前端凭证机制：硬编码密钥仅留 Node 侧读取。
   - **管理密钥（`BLUEPRINT_SAVE_KEY`、`PROXY_API_KEY`）**：只存服务端环境变量，管理员发布时在前端手动输入校验，绝不打进 JS 包。
   - **防自动化会话令牌（`AUTH_SESSION_SECRET`）**：仅由 Node 侧在限流 + 同源/CORS 白名单校验后通过 `POST /api/auth/session` 签发 1 小时 `HttpOnly` Cookie，前端完全匿名启动、零静态密钥。
   - **纯前端静态 mock 模式**：保持完全匿名，无需任何鉴权流程。
2. **REST / WebSocket 统一到单一房间存储文件（取消双轨文件割裂）**
   - `server/fileStore.ts`：所有房间（包括 `atlas-main`）统一读写 `<dataDir>/rooms/<key>.json`（单一事实源 `{ revision, blueprint, updatedAt }`），不再分裂为 `blueprint.json`、`room-blueprints/` 与 `rooms/` 三处文件。
   - REST（`/api/rooms/<path>/blueprint`）与 WS（`/ws/<path>`）彻底退化为同一房间数据的两种通信通道。
3. **新增 WebRTC P2P DataChannel 作为第三传输通道**
   - 新增 `src/core/webrtcMesh.ts`：确定性发起方防 glare、`RTCDataChannel('atlas-crdt')` 点对点直传 CRDT 增量帧，NAT/防火墙受限时自动静默回落至 WS 中继。
   - `server/roomServer.ts`：新增定向信令中继（`rtc_offer`、`rtc_answer`、`rtc_ice`）与入房成员列表（`peers`），复用现有 `/ws/<roomPath>` 连接完成 WebRTC 建连，无需额外部署信令服务器。
   - `src/core/roomClient.ts`：接入 `RoomWebRtcMesh`，连入房间自动与同房成员建立 P2P DataChannel，收到 P2P 帧直接交给 CRDT 合并管线。
