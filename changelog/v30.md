# v30 — 扇出（Fan-out）并发驱动，并修掉并发化引入的重复投递与丢更新

> 发布日期：2026-11-23

## 修复（Fixed）

- **扇出示例此前只驱动单个最新子控件**：`src/core/seedBlueprint.ts` 的「示例：一键创建并联动控件」原先用 `emit(vars.lastChildId, 'ping', ...)`，`out-1` 扇出多条连线时只有最新那张子卡收到消息。现改为 `emitDownstream('ping', { text })`，「读子控件变量」同步改为遍历 `widgets.outputs()` 汇总全部下游。
- **多下游扇出串行等待**：`src/App.tsx` 的 `executeUnifiedWidgetScript` 中，`emitOps` 事件派发与下游连线自动刷新原先都是 `for ... await` 串行，N 个下游要排队 N × 单次执行耗时。现改为 `Promise.all` 并发，扇出分支同时驱动。

## 改进（Changed）

- **常驻 Worker 池容量 3 → 6**：`src/core/scriptSandbox.ts` 提升 `MAX_POOLED_WORKERS`，避免并发扇出宽度超过池容量时退化为 Worker 冷启动。同步修正了原注释仍写「最多保留 3 个」与实际常量不符的问题。

## 已知遗留 / 未生效项

- **`npm test` 仍未接入 `deploy-pages.yml`**：按 `AGENTS.md` 保护清单，未修改仓库维护版 workflow，测试未进 CI 门禁。
- **`emitDownstream` 的载荷合并语义**：同一出口多条边指向同一控件时按控件去重后只投递一次；若脚本对同一目标、同一事件触发了多次 `emit`，载荷会被合并为数组传给接收方（单次触发时仍是原对象，接收方无需区分）。这是并发化的必要代价，文档未描述该边界。

## 验证

- **种子脚本安全 + 语法预检**：4 个带脚本的种子节点全部通过 26 个 token 黑名单检查与 `AsyncFunction` 编译，0 问题。
- **扇出去重**：`emitDownstream` 按 `dst.id` 去重后再计入 `count`，避免重复边导致计数虚高与接收方重复触发；`seedBlueprint` 内 `uniqueOutputs()` 同口径去重。
- **并发丢更新**：`executeUnifiedWidgetScript` 按 `targetId + event` 归并 `emitOps`，防止同一脚本被多个 Worker 并发执行后由 `setOverlay` 后写者覆盖前写者。
- **状态写入**：扇出各分支均走 `setOverlay(prev => ...)` 函数式更新并写入独立的 `runtimeVars[tid]`，并发不互相覆盖。
- `npm test`：17 / 17 通过。`npm run typecheck` / `npm run build` 由 CI 执行。
