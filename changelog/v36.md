# v36 — 修 v35 三环裁剪的两处实现缺陷（脏签名漏字段、空闲预取被反复取消）

> 发布日期：2026-11-23

## 修复（Fixed）

- **分块脏签名漏掉节点渲染字段**：`src/core/chunkManager.ts` 的签名原先只含 `id/x/y/width/height/color/title`，漏了 `body`、`category`、`locked`。改这些字段时签名不变 → 分块不标脏、`version` 不递增 → `ChunkTileCache.get()` 命中旧瓦片，画面停留在旧内容。已补齐上述字段（`body` 计入长度、`locked` 计入布尔位）。
- **annotation 签名只取文本前 32 字符**：改动发生在第 33 字符之后时不改变签名，同样留下过期瓦片。已补上文本末 16 字符作为尾部指纹，配合原有长度校验收紧盲区。
- **空闲瓦片预取实际不生效**：`scheduleIdleTilePrefetch()` 在每次 `draw()` 结尾都会调用，而 `draw()` 在平移/拖拽时近乎每帧触发（`store.subscribe` + `requestAnimationFrame` 自递归）。原实现每次都先 `cancelIdlePrefetch()` 再重排，导致 `requestIdleCallback` 永远等不到执行窗口，Ring 2 预烘焙形同虚设。已改为「已排队则跳过」，让已排程的预取跑完再排下一次。

## 改进（Changed）

- **预取注释补充因果说明**：在 `ChunkUnderlayCanvas.tsx` 写明为什么不能无条件 cancel，避免后来者重构时再次引入。

## 已知遗留 / 未生效项

- **`prevViewportCenterRef` 在 `useMemo` 内被赋值**：`App.tsx:202` 的 `threeRingBounds` 计算在 `useMemo` 里写入 `prevViewportCenterRef.current`，属渲染期副作用。`useMemo` 不保证只执行一次（StrictMode 双调用、依赖变更重算），平移方向判定因此不严格幂等。**未改**：实际影响仅是方向前瞻偶发取到上一次的值，最多导致预加载偏移一格，不影响正确性。彻底修需把方向计算移出 `useMemo` 到 `useRef` + 比较逻辑里。
- **`renderedScriptsRef` 只增不清**：首帧脚本渲染按 Ring 1 过滤，`renderedScriptsRef` 记录已渲染 id。v35 保留了 v34 的四处 `clear()`，但若将来新增节点删除路径未同步清理，同 id 重建会被跳过。
- **`widgets.connect()` 仍绕过 `validateDagConnection()`**：延续 v30 起的遗留项。
- **`npm test` 仍未接入 `deploy-pages.yml`**：按 `AGENTS.md` 保护清单未修改仓库维护版 workflow。
