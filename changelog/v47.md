# v47 — 检查器脚本控制台日志面板 + `onChange(key, fn)` 变量响应式订阅

## 变更动机
补齐历史隐患清单第 8、9 项中影响日常写脚本调试体验的两块能力：
1. 脚本里 `log(...)` 过去只闪现一条 3.5 秒顶部浮条，报错或链式联动时难以按节点回溯。
2. 变量变更后需要靠手写重复逻辑维护派生字段，缺少细粒度的变量响应式订阅钩子。

## 核心改动
- `src/core/scriptSandbox.ts`：
  - 新增 `onChange(key | keys[] | '*', (nextVal, prevVal, key) => ...)` 沙箱 API，同步纳入 `validateScriptSyntax()` 编译预检。
  - 在 `click` / `submit` / `message` 回调执行后自动 diff `vars` 触发匹配的 `onChange` 订阅（支持多级派生联动，内置 `MAX_REACTION_PASSES = 3` 防止 `a <-> b` 死循环，通配符 `'*'` 默认跳过 `contents` 声明式 UI 重建），之后重跑顶层刷新 `vars.contents`。
  - 新增 `trigger.kind === 'varsChanged'` 触发通道，支持外部编辑变量时直接触发 `onChange`。
- `src/components/NodeInspectorPanel.tsx`：
  - 在统一脚本编辑器下方新增按节点隔离的深色 **脚本日志面板**（`ScriptConsoleEntry`），显示时间戳、触发来源标签（`click:*` / `submit:*` / `msg:*` / `var:*` / `btn:*` / `render`）与日志/错误分级配色，支持按“筛错误”过滤及一键清空。
- `src/App.tsx`：
  - 新增 `scriptLogsByNode`（单节点环形保留最近 50 条）与 `appendNodeLogs` / `handleClearScriptLogs`，接入统一脚本与旧版按钮脚本的日志与报错采集。
  - 在属性检查器修改或删除变量（`handleUpdateDefaultVar` / `handleDeleteDefaultVar`）时同步更新 `runtimeVars` 并向带脚本节点派发 `varsChanged` 事件，立即驱动 `onChange`。
- `tests/scriptSandbox.test.ts`：新增 3 项 Worker 真实执行单测，覆盖 `onChange(['price', 'qty'])` + 链式派生、`onChange('*')` + 循环护栏、以及 `varsChanged` 外部变量修改触发。
