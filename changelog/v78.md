# Atlas Hybrid Canvas v78 — 解决 5 大内在架构矛盾

## 本次架构收敛与修复
1. **消除「静态密钥硬编码前端」与「短期会话令牌」的自相矛盾**
   - `server/server.ts`：`POST /api/auth/session` 接入速率限制（`checkProxyRateLimit`）；新增 `AUTH_ALLOW_PUBLIC_SESSION` + `CORS_ALLOWED_ORIGINS` 配置，支持纯前端公网站点按 `Origin` 白名单签发短期 `HttpOnly` 会话 Cookie，无需再将 `PROXY_CLIENT_TOKEN` 通过 `VITE_PROXY_CLIENT_TOKEN` 暴露在前端静态包中；`.env.example` 明确警示勿在公网构建中注入 `VITE_PROXY_CLIENT_TOKEN`。
2. **打通「REST 蓝图底座」与「WS 协同快照」双轨存储割裂**
   - `server/roomServer.ts`：`attachRoomServer` 新增可选 `loadFallbackBlueprint` 回调（新建空房间且无 `rooms/<key>.json` 快照时，自动水合对应房间的已发布蓝图），并暴露 `syncPublishedBlueprint(roomName, blueprint)` 与 `clientIp`（供 RPC 限流使用）。
   - `server/server.ts`：任何房间通过 `POST /api/rooms/*/blueprint/publish` 或 `POST /api/blueprint/publish` 发布成功时，同步调用 `roomServer.syncPublishedBlueprint` 刷新该房间内存态、磁盘协同快照并向在线成员广播，彻底消除两份状态分叉。
3. **隔离「LocalOverlay」跨房间状态串台**
   - `src/core/layeredStore.ts`：`loadLocalOverlay(roomPath)`、`saveLocalOverlay(overlay, roomPath)`、`scheduleSaveLocalOverlay(overlay, delayMs, roomPath)` 与 `subscribeCrossTabOverlay` 全部按规范化房间路径隔离（默认房间沿用旧 key 兼容既有本地数据），跨页签同步亦附带 `roomKey` 过滤。
   - `src/hooks/useOverlaySync.ts` & `src/App.tsx`：切换 `roomName` 时先落盘旧房间待写入补丁，再异步加载目标房间的独立 `LocalOverlayState` 并重置指纹基线，杜绝跨房间节点补丁污染。
4. **修复跨源部署与子路径部署的三重链路冲突**
   - `src/core/roomPath.ts` & `src/App.tsx`：`extractRoomPathFromBrowserLocation` 自动剥离 `import.meta.env.BASE_URL`（如 GitHub Pages 的 `/<repo>/`），子路径部署下改用 `?room=<roomPath>` 同步地址栏，不再把仓库名误判为房间名、也不再改写导致刷新 404。
   - `server/server.ts`：新增 `CORS_ALLOWED_ORIGINS` 跨源白名单支持（`Access-Control-Allow-Origin`、`Access-Control-Allow-Credentials: true`、`OPTIONS` 预检及跨源 HTTPS `SameSite=None; Secure` Cookie），打通跨源 `/api/auth/session`。
   - `server/roomServer.ts` & `server/server.ts`：WS RPC 回环转发附带内部密钥签名校验的 `X-Atlas-Rpc-Ip` 真实客户端 IP，解决全站 RPC 用户共享 `127.0.0.1` 限流桶的问题。
5. **收口服务端冷房间内存句柄上限**
   - `server/fileStore.ts`：`createRoomBlueprintStoreRegistry` 从无界 `Map` 升级为有界 LRU 缓存（默认上限 100 个活跃房间句柄），超出后自动淘汰最久未访问句柄（数据已安全落盘，下次访问无缝重新水合）。
