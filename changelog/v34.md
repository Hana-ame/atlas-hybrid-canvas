# v34 — PDF 上传改二进制直传，上限放宽到 50MB

> 发布日期：2026-11-23

## 改进（Changed）

- **PDF 上传不再走 base64**：`POST /api/pdf/upload` 改为接收 `Content-Type: application/pdf` 的原始字节，服务端用 `express.raw()` 精确接住请求体，前端直接 `fetch(url, { body: file })`。
  - 少了 base64 的 4/3 编码膨胀——原来 15MB 文件编码后恰好 20.00MB，会撞在 `express.json` 的 limit 上被提前 413 掉，连路由里的友好提示都到不了。现在体积按真实字节算，不存在这类边界耦合。
  - 少了 `FileReader.readAsDataURL` 的全量内存读入，大文件不再先转成一整条超长字符串再发出。
  - 文件名改由 `X-Pdf-Filename` 头传递，中文名前端 `encodeURIComponent`、服务端 `decodeURIComponent` 解回。
- **上传上限 12MB/15MB → 50MB**：前后端统一到 `50 * 1024 * 1024`。服务端用 `PDF_UPLOAD_MAX_BYTES` / `PDF_UPLOAD_MAX_LABEL` 两个常量统管上传校验、代理拉取校验与错误文案，避免三处数字各写各的。
- **`express.json` 的 limit 从 24mb 回落到 1mb**：它现在只承载 blueprint 这类小 JSON，PDF 走的是独立中间件，不需要再为大文件留余量。
- **代理拉取 PDF 与上传共用同一上限**：`/api/proxy/binary` 原本独立写死 15MB，现改为引用同一常量，避免「能上传却打不开代理的同类文件」。

## 修复（Fixed）

- **上传失败时无任何提示**：原代码在服务端返回非 2xx 时静默降级为本地 Blob URL，用户不知道自己选的「上传」其实没到服务端。现在会读出服务端 `error` 字段显示，兜底给「上传失败（HTTP xxx），已改用本地文件预览」。
- **请求体超限的 413 暴露 Express 默认错误页**：`express.raw` 的 limit 在进入路由前生效，超限时会返回 Express 的 HTML 错误页。新增兜底错误中间件（注册在所有路由与静态资源之后），把 `entity.too.large` 转成统一 JSON 文案，其余错误也统一成 JSON，并对 `res.headersSent` 做了透传保护。

## 已知遗留 / 未生效项

- **50MB 上限只对自托管后端有效**：纯静态 Pages 部署没有 `/api/pdf/upload`，上传一律降级为浏览器本地 Blob URL（刷新即失效）。
- **`/api/pdf/:id` 仍无鉴权**：id 为 8 字节随机，链接泄漏即可被读。
- **压缩流 PDF 的页数统计仍不可用**：明文正则扫不到 FlateDecode 压进 `/ObjStm` 的页对象，UI 显示「共 ? 页」。
- **`widgets.connect()` 仍绕过 `validateDagConnection()`**：待处理。

## 验证

- **base64 残留清查**：PDF 相关代码中 `base64` / `readAsDataURL` / `FileReader` 已无逻辑用法，仅剩注释说明。`App.tsx` 与 `AnnotationNode.tsx` 中的 `FileReader` 属背景图上传，未改动。
- **前后端阈值一致性**：服务端 `PDF_UPLOAD_MAX_BYTES`、前端 `file.size <= 50 * 1024 * 1024`、上传按钮 `title` 文案三处均为 50MB。
- **语法检查**：`server/server.ts`、`src/core/pdfHelper.ts` 通过 Node 类型剥离解析，无语法错误；`server.ts` 括号平衡校验通过。
- **依赖核对**：`express@^4.21.2` + `@types/express@^4.17.21` 原生支持 `express.raw`，未新增任何依赖。
- `npm test` / `npm run typecheck` / `npm run build`：由 CI 执行，本机不跑（`AGENTS.md` 禁止本地构建）。
