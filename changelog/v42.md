## 本版修复

### 阻断

**`PROXY_API_KEY` 在上游配置非法时回落注入给白名单主机**

v41 把 `injectSecret` 从「上游 **或** 白名单」改成「配了上游就只看上游」，方向正确。但它用 `upstreamHost` 做「是否配置了上游」的判据：

```ts
const injectSecret = upstreamHost
  ? host === upstreamHost
  : allowedHosts.length > 0 && hostMatchesAllowlist(host, allowedHosts);
```

`upstreamHost` 来自 `new URL(upstreamBase)`，解析失败时被 `catch` 兜成空串。也就是说 `PROXY_UPSTREAM_BASE_URL` 只要写错（少写协议、拼错、留了个空格后跟非法字符），`upstreamHost` 就是 `''`，条件退化为假，**直接回落到 `allowedHosts` 分支**——而 `allowedHosts` 里正是演示用的 `httpbin.org`。密钥照发。

实测（`upstreamBaseUrl: 'not a url'`，`allowedHosts: ['httpbin.org']`）：修复前 `https://httpbin.org/get` 返回 `injectSecret: true`。**v41 声称堵住的洞，在配置写错时原样存在。**

修复：判据改用 `upstreamBase` 原始字符串。

```ts
const injectSecret = upstreamBase
  ? host === upstreamHost // upstreamHost 为空时恒为 false，即配置非法时不向任何主机注入
  : allowedHosts.length > 0 && hostMatchesAllowlist(host, allowedHosts);
```

修复后同一输入返回 `injectSecret: false`，且白名单主机仍可正常代理（只是不带密钥），未配置上游时保持原有白名单语义。
